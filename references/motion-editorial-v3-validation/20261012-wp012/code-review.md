# 隔离代码与安全复审

范围：`experiments/motion-editorial-v3/`、两条样片目录中的准备/检查/渲染/包装脚本与 HTML。不是生产集成复审。

主代理执行只读核对，并安排独立代码复审及 Python 专项复审。WP0 的 38 项测试经主代理独立重跑；专项复审未发现阻止隔离实验的高危问题。未安装额外 lint 工具，不把未运行工具记为通过。

## 发现与处置

| 问题 | 级别 | 处理 |
| --- | --- | --- |
| 软件准备阶段可能重写来源记录后复用旧媒体 | Medium | 首写前核验冻结输入，已有准备媒体即拒绝；不把旧媒体绑定新证据 |
| 手写风格窗口误标 `owner=video-use` | Medium | 两类均明确为 isolated style excerpt / derived non-authoritative map；原 EDL 只读 |
| strict check 只绑 HTML 或布尔结果，没有所有实际渲染依赖 | Medium | 增加本地依赖白名单、组成清单和哈希比较；首轮历史缺口另记录事后核验，不倒填 |
| 软件包装仅凭 raw 文件存在就写成功 | Medium | 要求成功 render receipt、completed ledger、输出位置与 raw SHA 一致 |
| 预算常量与 HTML 真正时长可能不一致 | Medium | 启动前严格校验当前方向 duration/fps，拒绝其他时长；实际输出仍需 probe |

没有发现 CRITICAL/HIGH；不等于覆盖了所有潜在缺陷。新保护在首次渲染之后才补齐，首次候选不能被称作已预先通过这些新门。真人另写新的 gate-v2 检查记录，不覆盖首次检查；软件修订版在新门下重新检查与渲染，v1 保留为历史候选。

## 非代码质量发现

软件 v1 的 1.6 秒帧显示弹窗已经过渡，旧定位/取景退场仍在发生，违反目标变化时退出要求。主代理确认后使用已批准的唯一修订预算，仅提前退出时机，不调整产品方向。技术检查不能发现或替代这一实际画面检查。最终修订状态与证据见软件 `revision-02`；不把旧版描述成无缺陷。

完整听审、审美、是否值得继续看仍由用户决定。代码复审不会将这些状态改成通过。

复审确认：真人新增 7 项无渲染门测试通过、34 项 manifest 哈希一致、ZIP CRC 通过；软件新增 7 项无渲染门测试通过。修订目录不覆盖软件 v1，第二次 ledger 明确 attempt=2。跨两项目的累计 35 秒由本次主任务台账核算；隔离脚本不提供通用跨项目额度服务，不能宣称已实现正式全局预算管理。

修订最终检查：首次 check 在运行期间检测到 HTML 改变，exit 90 阻止执行，失败记录保留。固定 HTML 后重检与渲染输入前后哈希一致。主代理查看实际修订输出 1.45 秒与 1.60 秒帧，前者取景已复原且定位已退，后者保留真实弹窗过渡、没有新增定位残留。未将原 UI 自身转场当作新增动效缺陷，也未修改源片。

独立复审最终结论：软件修订 check/render/ledger 的 6 项组成哈希与当前文件一致，raw SHA 与 attempt=2 completed 记录一致，8 项交付清单哈希与 ZIP CRC 通过；无遗留 Critical/High/Medium 代码发现。结论仅允许停在本轮隔离样片人工门，不构成正式集成许可。
