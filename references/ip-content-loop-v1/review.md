# 设计复审

2026-10-02；作者自审。不是独立专家评审，也不是用户批准。

| 问题 | 裁决 |
| --- | --- |
| 先前分析称“缺少指标反馈”，但已有代码 | 已纠正；扩展已有 metrics/feedback，不重复实现 |
| 单集 brief 与 editorial_intent 重复 | brief 是来源和策略补充，已有 promise ledger 保持权威 |
| 学 Hypit 会改变 preservation 目标 | 只采纳关系/锚点/复用方法，生成任务单独路由 |
| 标题/封面更吸引会不会夸大 | 同一证据 ledger；无证据数字与结果不能升级成事实 |
| 内容评分会强制阻止普通剪辑 | 仅建议；由用户任务决定，必要事实门继续按既有合同 |
| 新字段会使老项目失效 | schema 14 内存迁移，默认关闭，关闭零侧层读取/输出 |
| 轻量模式会否跳过审核 | 只减少可选实验，必要质量与人工门完全相同 |
| “跨视频学习”会夸大因果 | 口径/来源/窗口对齐，独立发布去重，仅产出假设和实验候选 |
| 未来人设被系统自动修改 | 共享策略只读，候选不能写 profile、approved、production_default |
| 研究借鉴变成源码许可污染 | 独立方法编写，未 vendor 第三方代码，记录 Hypit 附加许可 |
| 安装成功是否等于生成成功 | 分别报告 CLI、素材检查、运行时、真实视频与审美，不能跨级 |

待用户批准的唯一设计决定：采用默认关闭的经营侧层，按照 WP0–WP5 接入已有
Director。具体个人定位和真实样片继续用后续任务的既有审核门。无需在本次
批准时决定自己的受众、产品价格或商业模式。

接受的局限：v1 不自动接入 Hypit renderer、不自动发布、不验证商业效果；
人工可编辑性需实际编辑器测试；素材语义与审美不能由 schema 自动证明。
