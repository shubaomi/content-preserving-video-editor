# Draft directory and version compatibility strategy

## Directory lifecycle

```text
<project>/work/director/manual-finish/jianying-native-draft-v1/
  staging/<build-id>/
  published/<build-id>/
    native-draft/
    assets/
    adapter-plan.json
    draft-package-manifest.json
    compatibility-report.json
    README-中文.md
  install-proposals/<build-id>.json
  canary/<build-id>/
```

Generation writes only under `staging`, validates the complete inventory, then
atomically promotes a new directory to `published`. It never writes directly to
the Jianying draft store. An install proposal records the exact new target path
and expected empty/nonexistent state. Actual installation is a separate future
command and must require explicit authorization.

## Existing-draft prohibition

- Target draft ID is generated by Director and cannot be caller-selected to an
  existing name.
- If any target path exists, installation fails closed; no merge/overwrite mode.
- No template is loaded from the user's draft store.
- No draft database, cache, cloud folder, or account file is read or copied.
- Rollback deletes only the exact newly installed draft after verifying its
  install receipt and current inventory; drift requires manual handling.

## Asset modes

- `linked`: draft references current package-local assets by absolute path;
  default for the short canary, minimal storage, project cannot be moved freely.
- `portable`: assets are copied into the published bundle after size-budget and
  rights checks; still requires an install-time path rewrite if the editor needs
  absolute paths.

The automatic master is referenced as a locked comparison asset, never placed
on an enabled export track in layered mode.

## Compatibility identity

Every build records:

- OS and architecture;
- detected Jianying executable version and product name, without launching it;
- adapter ID/version/package hash/license;
- adapter serialization profile and draft-layout signature;
- canonical plan, NLE package and asset hashes;
- compatibility maturity and exact canary receipt if any.

Unknown editor version, unknown layout signature, missing dependency hash, or a
version outside the exact approved compatibility tuple blocks generation or
installation. Major/minor compatibility is never inferred from a nearby version.

## Initial version policy

The implementation may fixture-test against `pyJianYingDraft 0.3.0`, but no
Jianying release is marked compatible in this design. The first exact installed
version becomes a candidate only after a real short canary. Automatic open and
export remain disabled even when the library exposes them.
