# 软件产品介绍：从真实界面开始（隔离短样，不是 Director 新阶段）

当用户要介绍一个软件但没有录好的原片，先问缺的：**产品或测试地址、给谁看、想让观众看到哪个任务完成**。已有录屏/真人解说仍用 guided intake。产品只有文案时可先出脚本、待证主张和补拍清单，不虚构操作；不能证明实物手感或性能的照片也不当实测。不要要求用户写 JSON。

**先区分交付物。** 如果要验证“这个操作能否得到这个结果”，下面的无声短样可以交付为操作证据。如果要让观众通过解说和动效了解产品，请把已核实的界面交给 HyperFrames，按[产品动效与声音验收](product-motion-acceptance.md)制作创意样片；不能把试点导出的无声 MP4 当作有声介绍片交付。这个区分不改变试点的权限或输出。

## 本轮设计与边界

| 约定 | 最小实现与验收 |
|---|---|
| DEMO-1 先定一件事 | 助手写一个用户任务：起始困境 → 一个可见操作 → 可见结果。每镜只配一条短解释，逐条写出预期在画面里看到的真实文字；原始项目与实际运行界面优先于营销文案。把证据不足的卖点删掉或列为待确认。 |
| DEMO-2 捕获，不模拟 | 在用户授权的、仅含演示数据的本机测试站点，以全新 Chromium 会话访问明确列出的只读资源。不启动用户项目、不扫描目录、不复用账号。助手先读产品提供的说明或已授权界面拟定步骤；工具不从任意 URL 猜测操作。不得访问生产、发送表单、使用真实客户资料、读取口令、安装依赖或调用付费服务。 |
| DEMO-3 可复验短样 | 每一步等实际可见状态，点击后必须出现之前不可见的结果；不成立就停止，不能靠剪辑造出成功。导出原始 PNG、逐镜说明 SRT、带说明的无声 MP4 和哈希清单。截图按秒停留，不是连续录屏、真人字幕或性能测速；说明与截图是否匹配仍需看画面。 |
| DEMO-4 隔离与退回 | 只在新目录写项目私有样件，不覆写、不推送媒体。已有 Director 的默认输入、19 个阶段、视频转录、HyperFrames 创意渲染、样片审批和成片授权均不变。移除本入口即可退回。短样不是正式母版，不得用它伪造有声源片、EDL 或批准。 |

## 实际使用

只对可信的本机演示应用操作。先向用户简述任务、地址、资源、点击和产出；确认演示数据、操作权限后再运行。脚本的确认开关是调用者声明，不是身份认证。不要为“跑通”放开网络。需要登录、实时后端、上传、外部域名、WebSocket、摄像头、桌面原生或移动 App 时，改用用户授权的脱敏录屏／截图；说明缺口。不要启动或修改生产服务。

助手在媒体项目中写 UTF-8 场景文件（示例字段见下；资源路径与文案按产品替换）。素材、实际网址、输出都不进 Skill 仓库。工具只向指定的本机端口 GET 明列的静态路径；开发者仍需保证这些 GET 无副作用。受控桌面浏览器不是抵御恶意网页的安全沙箱。

```json
{"url":"http://127.0.0.1:8080/demo","paths":["/demo","/static/demo.js"],
 "steps":[{"expect":"全部任务","copy":"先看本周任务。","seconds":3},
          {"click":"只看待办","expect":"待办任务：2 项","copy":"筛选后，只保留待办任务。","seconds":4}]}
```

在 Skill 根运行 `python pilots/software-demo/software_demo_pilot.py <场景.json> <不存在的本地输出目录> --confirm-demo-capture`。要求现有 Python Playwright、Chrome、含 libass/libx264 的 FFmpeg 和 ffprobe；没有就报缺项，不自行安装。复核画面与说明后再给用户看。用户要改文案保留原证据；若改步骤、产品版本或结果，建新目录重新验证。要加入连续操作、创意动效或真人声轨，按其实际来源走原有剪辑流程或另行确认创作简报；不从说明字幕伪造逐词转录。

这是对经许可静态响应的离线浏览器回放：960×464 界面加独立说明栏，输出 960×540、24 fps。需要保留站点安全响应头、会话状态或压缩响应的产品，本试点会拒绝，不移除策略后重试。场景与输出放在非云同步的本地私有目录；不使用共享盘。可用 `python pilots/software-demo/test_software_demo_pilot.py` 执行回归，或加 `--render-example <新的本地目录>` 在虚构阅读清单上实际验证、生成 7 秒样片，不接触用户产品。

## 开源方法取舍（2026-11-14，一手资料）

- [Demo Machine](https://github.com/45ck/demo-machine)：借用“可重跑的演示场景”思想，把路径、动作和停留时间从渲染代码拆开；不采用自动启动应用或任意执行命令。
- [Runcast](https://github.com/datafloem/runcast)：借用“演示同时验证流程”，让结果断言决定是否收镜，不录一条明知失败的成功演示。
- [Editly 的 clip/layer 示例](https://github.com/mifi/editly/blob/master/examples/commonFeatures.json5)：用可修改的时长、画面、说明分层，先做低成本预览。这里只编码静态实拍帧和说明，不让 FFmpeg 接管创意动效。
- [HyperFrames](https://github.com/heygen-com/hyperframes)：保留为正式创意制作端。其产品发布片路由说明不等于当前 Director 已有同名后端或这台机器装齐工作流。

这些是独立实现的方法借鉴，不复制或安装上述第三方项目。本次验收限本机虚构测试产品的实际浏览器与短样输出；不代表任一真实客户产品、审美或发布验证。
